# про.стим облачные проекты и браузер

Пользователь выбирает источник проекта в веб-приложении. Для первого интерфейса предусмотрены GitHub, Google Drive, Яндекс Диск и папка текущего устройства. Облачные режимы позволяют работать с файлами в аккаунте пользователя через разрешения провайдера. Исполнение команд и сборок определяется выбранной рабочей средой.

## GitHub

Репозиторий хранится в аккаунте пользователя. Интеграция может читать выбранные файлы, создавать ветки и pull request в пределах выданных разрешений. Сборки выполняются в CI пользователя или подключённой среде. GitHub App позволяет ограничить доступ выбранными репозиториями. [GitHub Apps](https://docs.github.com/en/apps/creating-github-apps/about-creating-github-apps/about-creating-github-apps)

Текущий интерфейс позволяет прочитать поддерживаемые текстовые файлы из корня публичного репозитория по его ссылке. Приватные репозитории, запись и pull request подключаются через авторизацию приложения.

## Google Drive

Вход через Google подтверждает личность пользователя. Разрешение на работу с Drive запрашивается отдельным OAuth-потоком. Google Picker предоставляет интерфейс выбора файлов и папок после настройки Google Cloud project и необходимых ключей приложения. [Google Identity Services](https://developers.google.com/identity/oauth2/web/guides/overview), [Google Picker](https://developers.google.com/workspace/drive/picker/guides/web-picker)

Scope `drive.file` даёт доступ к выбранным пользователем или созданным приложением файлам. Доступ ко всем существующим дочерним файлам выбранной папки нужно проверить в интеграции. Более широкие Drive scopes имеют дополнительные требования к проверке приложения. [Разрешения Drive API](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

Синхронизированная папка имеет облачную копию. После синхронизации сервис может работать с этой копией при выключенном компьютере. Изменения на компьютере и в облаке согласуются клиентом синхронизации. [Синхронизация Google Drive](https://support.google.com/drive/answer/13401938?hl=en)

Для фоновых задач используется согласованный серверный OAuth code flow с защищённым хранением токенов. Для открытой браузерной сессии возможен клиентский поток доступа. Пользователь видит предоставляемые права и может отозвать подключение. [Google OAuth code model](https://developers.google.com/identity/oauth2/web/guides/use-code-model)

## Яндекс Диск

OAuth-приложение получает права чтения, записи либо доступа к собственной папке приложения. Режим папки приложения использует `app:/` в аккаунте пользователя. Работа с произвольной существующей папкой требует соответствующих прав, а выбранный путь дополнительно проверяется приложением. [API Яндекс Диска](https://yandex.ru/dev/yandex-360/disk/rest/ru/concepts/quickstart), [Папки приложений](https://yandex.ru/dev/yandex-360/disk/rest/ru/concepts/app-folders)

## Папка на текущем устройстве

В поддерживаемом браузере `showDirectoryPicker` предоставляет доступ к выбранной папке. Пользователь может читать текстовые файлы, редактировать их и сохранять изменения после выдачи прав записи. Требуются HTTPS и действие пользователя. Браузер работает с файлами того устройства, на котором открыт сайт. [File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)

В текущем интерфейсе читаются поддерживаемые текстовые файлы до 512 КБ, с ограничением глубины и количества. Перед сохранением проверяется, совпадает ли файл на диске с прочитанной версией. В браузерах без directory picker используется импорт через выбор папки. Импортированные файлы можно просматривать, редактировать в памяти и скачивать.

Системные команды, управление рабочим столом и папкой другого компьютера обслуживаются локальным агентом или выбранной серверной средой. Эти режимы описаны в [удалённой работе](remote-work.md).

## Основа интерфейса

Текущая версия сайта содержит три основных раздела — «Лента», «Steam» и «ИИ-мир». Google Drive и Яндекс Диск показывают демонстрационный проект с обозначением состояния подключения. Настройка OAuth, реальные модельные запросы и отправка заявок подключаются на следующем этапе. Локальная папка и чтение публичного GitHub доступны как браузерные функции.
