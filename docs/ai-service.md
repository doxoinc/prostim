# про.стим ИИ сервис

ИИ-раздел предоставляет пользователям из Молдовы и других поддерживаемых стран инструменты работы с собственными проектами. Пользователь выбирает модель и способ оплаты, задаёт бюджет и управляет задачей со своего устройства либо удалённо через сайт. Локальный агент выполняет операции с проектом, а модель вызывается через выбранную интеграцию.

## Аудитория и доступность

Сервис проектируется для пользователей из Молдовы и других стран, поддерживаемых выбранным провайдером. У OpenAI условия доступности распространяются на оператора приложения и его конечных пользователей. Молдова входит в список поддерживаемых стран. [OpenAI Services Agreement](https://openai.com/policies/services-agreement/), [Поддерживаемые страны OpenAI](https://developers.openai.com/api/docs/supported-countries)

Anthropic также поддерживает Молдову. При подключении учитываются местонахождение пользователя и условия для организаций, включая регистрацию, штаб-квартиру и определённое политикой владение или контроль. [Anthropic Supported Regions Policy](https://www.anthropic.com/legal/supported-regions)

Для первого пилота выбирается одна доступная API-интеграция. Подключение новых моделей учитывает условия провайдера, возможности локального агента и измеренную стоимость.

## Аккаунты и способы подключения

OpenAI предусматривает интеграцию API в приложение для собственных пользователей. Anthropic также допускает использование сервисов в продуктах, при этом перепродажа сервисов требует его явного одобрения. Для платного универсального прокси к Claude необходимо согласовать конкретную коммерческую модель. [OpenAI Services Agreement](https://openai.com/policies/services-agreement/), [Anthropic Commercial Terms](https://www.anthropic.com/legal/commercial-terms)

Платформа использует собственные пользовательские сессии. При подключении личного аккаунта провайдера пользователь проходит его официальный вход. Полномочия и оплата относятся к выбранной интеграции конкретного пользователя. [OpenAI Terms of Use](https://openai.com/policies/terms-of-use/), [Anthropic Consumer Terms](https://www.anthropic.com/legal/consumer-terms)

| Способ подключения | Применение в проекте |
| --- | --- |
| API-организация оператора | Локальный агент вызывает модель через шлюз, оператор оплачивает API и учитывает расход пользователя |
| Собственная API-организация пользователя | Агент использует личный ключ или официальное подключение биллинга пользователя |
| Официальная интеграция подписки | Пользователь предоставляет полномочия в пределах поддерживаемой программы или клиента |
| Самостоятельно размещённая модель | Оператор оплачивает вычисления и выполняет условия лицензии |

Предлагаемый MVP поддерживает оплату через API оператора и собственный API пользователя. Платёж за использование платформы и платёж за модель показываются в интерфейсе согласно выбранному варианту.

У OpenAI участвующие приложения могут через Sign in with ChatGPT отдельно запросить разрешение использовать доступный лимит подписки пользователя. Коммерческая интеграция зависит от участия приложения в программе. Она сохраняет территориальные условия. [Использование ChatGPT в других приложениях](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)

У Anthropic linked billing в beta связывает приложение с Claude Console-организацией пользователя. Провайдер выставляет счёт этой организации. Эта схема имеет собственные условия и ограничения подключения. [Anthropic linked billing](https://support.claude.com/en/articles/18467110-offer-linked-billing-in-your-platform)

## Использование готовых клиентов

Существующий клиент провайдера может выполняться на компьютере пользователя, а сайт передаёт команды его локальному процессу и показывает события. Для собственной коммерческой интеграции Codex используется API либо поддерживаемая авторизация Sign in with ChatGPT. Выбор программного интерфейса и способа входа учитывает условия размещения клиента в продукте. [Подключение Codex app-server к Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server), [Авторизация app-server](https://learn.chatgpt.com/docs/app-server)

Anthropic описывает размещение официального неизменённого Claude Code в продукте с сохранением встроенных способов входа. Каждый конечный пользователь авторизуется собственными учётными данными и оплачивает использование по своему договору. Для такого режима посредничество в оплате Claude требует иного соглашения. Приложение на Agent SDK использует предусмотренную API-аутентификацию либо отдельно одобренную интеграцию подписки. [Условия размещения Claude Code](https://code.claude.com/docs/en/legal-and-compliance), [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)

Для пилота предлагается собственный локальный агент с модельным API и нужными инструментами файлов и команд. Интеграция конкретного CLI добавляется после выбора поддерживаемого программного интерфейса и авторизации.

## Подписки и бюджет API

API имеет собственный учёт потребления и биллинг. Подходящие ChatGPT Pro и Business могут активировать ограниченные API-кредиты в принадлежащей владельцу API-организации. Размер, срок действия и покрываемые операции определяются правилами программы. Кредиты учитываются в планировании бюджета отдельно от лимитов пользовательского приложения. [API-кредиты подписок ChatGPT](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)

Подходящие Claude Max, Ultra и Team также могут получать API-кредиты в связанной Console-организации. Доступность кредита определяется тарифом и типом использования. При API-аутентификации Claude Code расход относится к API-биллингу. [API-кредиты Claude](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans), [Использование Claude Code](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-max-or-ultra-plan)

Сервис рассчитывает устойчивую цену по себестоимости использования. Временные кредиты могут уменьшить расходы конкретного периода. Тариф учитывает продолжение работы после исчерпания кредитов и лимитов.

## Выполнение запроса

1. Пользователь выбирает подключённый компьютер, проект, модель и способ оплаты, затем вводит запрос.
2. Сервис проверяет доступ к устройству и доставляет запрос локальному агенту.
3. Агент подбирает контекст из выбранных файлов и вызывает модель через установленный API-маршрут.
4. При использовании шлюза оператор проверяет доступный бюджет, отправляет запрос провайдеру и передаёт ответ агенту.
5. Агент выполняет разрешённые вызовы инструментов, продолжает цикл задачи и показывает результат в браузере.
6. История и изменения сохраняются локально. Платформа учитывает предусмотренные метаданные и фактический расход.
7. Пользователь может подготовить изменение в Git либо опубликовать выбранные материалы в ленте.

Ключ оператора хранится на сервере. Ключ пользователя может храниться в защищённом хранилище его устройства для прямых вызовов. Перед передачей данных интерфейс показывает провайдера, маршрут запросов и контекст задачи. [Связь устройств и хранение данных](remote-work.md)

## Работа с кодом и размещение проекта

Основной режим выполняет команды на компьютере с пользовательским проектом. Агент читает файлы, показывает diff, запускает проверки и работает с Git в пределах полномочий сессии. Полная история хранится на устройстве. Сервер обрабатывает передаваемые через него фрагменты запросов в соответствии с выбранным режимом хранения.

Пользователь может подключить собственную облачную машину как исполнительную среду. Проект размещается в его облачном аккаунте, а сервис обеспечивает тот же канал управления. Дополнительная рабочая среда у оператора требует согласования временной копии файлов, срока её хранения и удаления.

Полный рабочий стол рассматривается как дополнительный режим с передачей экрана и управлением вводом. Доступ к файлам, выполнение задач и публикация результата определяются полномочиями соответствующей сессии. [Режимы удалённой работы](remote-work.md)

## Себестоимость и тариф

В расчёт операции входят входные и выходные токены, платные инструменты провайдера, время вычислений, хранение и передача файлов. Для самостоятельно размещённой модели основными статьями становятся аренда оборудования, загрузка вычислительных ресурсов и сопровождение.

```text
Себестоимость = запросы к модели + инструменты + вычисления + хранение + трафик
Маржа операции = цена пользователю − себестоимость − комиссии оплаты
Результат месяца до налогов = сумма маржи операций − постоянные расходы сервиса
```

Предлагаемый первый тариф использует оплату потребления с пользовательским пределом расходов. Фиксированный пакет с включённым бюджетом рассчитывается после измерения типичных и интенсивных сценариев. Сравнение цены с VPN требует учитывать объём вычислений, входящий в тариф.

В интерфейсе отображаются цена выбранной модели, расход задачи, остаток бюджета и возможность остановить дальнейшее выполнение. Уже выполненные платные операции отражаются в расходе после отмены задачи.

## Ошибки и учёт

Задача получает состояния ожидания, выполнения, завершения, ошибки и отмены. Локальный агент хранит последовательность операций и результатов. Платформа связывает метаданные с пользователем, устройством, проектом и идентификатором запроса провайдера, если он предоставляется.

Повтор доставки возвращает существующую задачу по её идентификатору. При неизвестном результате обращения к провайдеру агент и шлюз устанавливают фактический исход перед повторным платным запуском. Возврат браузера к сессии восстанавливает её события из локальной истории. Пользователь видит состояние устройства и задачи.

Для одновременно выполняемых задач backend учитывает уже зарезервированный бюджет. По завершении резерв сверяется с фактическим расходом. Периодическая сверка с биллингом провайдера помогает выявить расхождения.

## Условия подключения первого провайдера

Для запуска нужно выбрать API, способ оплаты, ОС первого агента и полномочия рабочей сессии. Затем проверить запрос из браузера другого компьютера, локальные инструменты, потоковый ответ, Git, лимиты расходов, отмену и восстановление после потери связи.

Данные о доступности и тарифах выше приведены по состоянию на 25 ноября 2026 года. Перед подключением конкретного тарифа используются актуальные условия провайдера.
