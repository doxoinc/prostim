# про.стим веб-сервис

Адаптивный сайт с тремя разделами — «Лента», «Steam» и «ИИ-мир» — и небольшой сервер на Node.js. Сервер хранит аккаунты, ленту, комментарии, оценки доверия, переписку, заявки и связывает браузер с агентом на компьютере пользователя.

## Команды

Команды выполняются из папки `site/`. Нужен Node.js 20 или новее.

```sh
npm install
npm start
npm test
npm run build
```

`npm start` запускает сервер на `http://127.0.0.1:4173`. Порт меняется переменной `PORT` или флагом `--port`, адрес — переменной `HOST` (для доступа с телефона в той же сети: `HOST=0.0.0.0`). Данные пишутся в `data/db.json` и `data/uploads/`. Если задан `DATABASE_URL`, состояние и картинки хранятся в Postgres.

`npm run build` собирает `dist/index.html` — копию сайта без сервера. Она открывается файлом и работает в локальном режиме с `localStorage`.

`npm install` ставит две зависимости: `pg` для Postgres и `@anthropic-ai/sdk` для необязательных подсказок ИИ (см. «Комментарии»). Иконки приложения рисует `node scripts/icons.mjs`; запускать его нужно только после смены знака.

## Лента

У ленты три режима. Пока открыта лента, нажатие на «Лента» (или на точку рядом) раскрывает под ней список без подложки: «Для тебя», «Подписки», «Открытия»: белая черта под «Лента» падает вниз, вытягиваясь на лету, и ложится под текущий режим, режимы проявляются вокруг неё, а верх фото слегка темнеет, чтобы текст читался; при закрытии черта возвращается под «Лента»; в других разделах «Лента» просто открывает ленту. Цветная точка у «Лента» значит, что выбран не обычный режим. «Для тебя» — рекомендации. «Подписки» — посты авторов, на которых подписан, проекты, за которыми следишь, и репосты людей из подписок, свежие сверху; когда они кончаются, лента продолжается рекомендациями. «Открытия» поднимают темы и авторов, которых зритель ещё не встречал, и не показывают то, что он не любит. Выбранный режим запоминается.

После регистрации новый аккаунт один раз видит анкету: разделы, чем человек занимается, жанры и темы, авторы для подписки. Выбор становится стартовыми весами интересов (раздел +4, тема +3), а дальше их поправляет то, что человек реально смотрит. Анкету можно пропустить; если её просто закрыть, она откроется при следующем входе.

Порядок ленты подбирается под зрителя: интерес поста (поддержка, сохранения, комментарии, удержание) плюс его личные интересы, которые растут из просмотров и действий. Лента бесконечная: когда новые посты кончаются, карточка «Новое закончилось» говорит об этом, а дальше круг за кругом идут уже виденные, и недавние уходят назад. Свайп вниз в начале ленты обновляет подборку. Подробности — в [документации ленты](../docs/feed-and-mvp.md#выдача-и-рекомендации).

Открытый пост — страница в стиле магазина: галерея, главная кнопка по первой ссылке, факты и страница, которую автор собирает из блоков со своими цветами и шрифтами. Подробности — в [документации страницы проекта](../docs/feed-and-mvp.md#страница-проекта).

На карточках нет меток «Новое», «Для тебя», «Снова» и подобных: посты просто идут в ленте. Помечается только реклама (см. «Реклама и Плюс»).

Кнопка поста видна прямо на карточке в ленте, под описанием: сначала «Играть», если у поста есть демо, потом первая кнопка со страницы поста или первая ссылка магазина. Ссылки принимаются и без `https://` — `t.me/канал` или `мояигра.рф` сайт дополнит сам. Если у кнопки нет рабочей ссылки, редактор подсвечивает это под полем, а публикация останавливается на шаге «Страница».

| Что | Как работает |
| --- | --- |
| Пост по ссылке | На первом шаге публикации — поле «Заполнить по ссылке». Steam читается через его API (название, описание, жанры, платформы, цена, стадия, скриншоты), GitHub — через API и README, остальные страницы — по тегам Open Graph. Сервер копирует картинки к себе, а страницу поста собирает из описания: заголовок, абзацы, список особенностей. Заполняются только пустые поля |

На карточке появляется «Играть», демо открывается во весь экран внутри поста, внизу — «В желаемое Steam», «Следить» и «Поддержать». Если сайт демо запрещает встраивание, пост открывает его в новой вкладке |
| Обновления | Автор пишет обновления на странице поста: версия, заголовок, текст, картинка. Свежее обновление показывается строкой на карточке, поднимает пост в ленте у тех, кто за ним следит, и приходит им уведомлением |
| Следить за проектом | Кнопка «Следить» на странице поста, в меню «…» и в плеере демо |
| Репосты | «Поделиться» → «Репост». Посты, которые репостнули люди из твоих подписок, поднимаются в ленте; у профиля есть вкладка «Репосты» |
| Твоя лента | Меню «…» на карточке: «Не интересно», «Меньше про #тег», «Не показывать посты @автора». Полный список — в «Твоя лента» (шестерёнка у интересов в профиле или в настройках профиля): темы, теги и авторы, которых показывать больше, меньше или никогда |
| Поиск | Ищет по названиям, тегам, авторам, описаниям, блокам страницы и обновлениям; каждое слово должно найтись, совпадение подсвечено в отрывке |
| Фото без конца | Фото поста листаются по кругу: в карточке ленты, в галерее на странице поста и на весь экран после последнего снова идёт первое, а перед первым — последнее |
| Подгрузка | Пока виден один пост, картинки и видео двух следующих уже грузятся. В настройках можно включить экономию трафика |
| Кадр картинки | У картинок поста есть точка, которая всегда остаётся в кадре: кнопка «Кадр в ленте» на обложке показывает фото целиком, яркой рамкой — что видно в ленте, пунктиром — что на странице поста, и превью обоих вариантов. Нажатие или перетаскивание по фото двигает точку |
| Картинки на странице | У блока «Фото» есть форма: оригинал, квадрат 1:1, вертикаль 4:5 или широкая 16:9; для формы можно выбрать кадр так же, как для обложки |

## Аккаунты и доверие

Регистрация по нику и паролю, пароль хранится как scrypt-хэш, сессия — HttpOnly-cookie. Как ещё можно войти — в разделе «Вход и почта» ниже. В профиле видны подписчики, подписки и рейтинг. Любой пользователь может один раз оценить другого от 1 до 5 с отзывом. Статус («Новый», «Участник», «Надёжный», «Проверенный», «Осторожно») зависит от средней оценки и числа отзывов. Уровень растёт за проекты, поддержки, подписчиков, комментарии и отзывы. Вокруг аватарки — тонкое кольцо-шкала: бледная дорожка по всему кругу и светящаяся дуга от низа по часовой стрелке, тем длиннее, чем выше средняя оценка (4,0 из 5 — 80% круга); под аватаркой стоит сама оценка — 4,0, 4,7, 5,0. Без оценок видна только дорожка. Цвет шкалы — уровень, десять цветов от белого до радужного; с 5-го уровня она светится, с 14-го по ней бежит искра. Номер уровня показан плашкой под именем в профиле.

## Вход и почта

Способы входа:

- **Ник или почта и пароль.**
- **Код из письма.** При регистрации почта подтверждается шестизначным кодом. Потом по почте можно войти без пароля: код приходит письмом. Код живёт 10 минут, даётся 5 попыток, новый можно запросить через 45 секунд. На сервере хранится только хэш кода.
- **Google, Apple, Яндекс ID, GitHub.** Кнопки появляются, когда для провайдера заданы ключи: Google и Apple — во всю ширину, остальные по две в ряд. Новый человек получает аккаунт с ником из логина или почты (скрытая почта Apple `@privaterelay.appleid.com` в ник не идёт). Если подтверждённая почта уже есть у аккаунта, вход попадает в него. В профиле («Изменить профиль → Вход и почта») можно привязать почту и подключить провайдеры к уже существующему аккаунту.
- **Пароль.** В «Вход и почта» можно задать пароль (если аккаунт пришёл из Google или Apple) или сменить его — нужен старый. Кто забыл пароль, нажимает на экране входа «Забыл пароль? Войди по коду из письма»: 15 минут после входа по коду или через провайдер новый пароль ставится без старого (`POST /api/me/password`).

Apple отвечает не переходом, а POST-формой со своего сайта (`response_mode=form_post`), и cookie с `SameSite=Lax` к такому запросу не прикладываются. Поэтому сервер принимает форму на `POST /api/auth/oauth/apple/callback` и сразу переводит её в обычный `GET` на тот же адрес — с ним cookie приходят, и проверка `state` та же, что у остальных. Имя Apple присылает только при первом входе, в поле `user` этой формы; сервер передаёт его дальше.

Переменные окружения на Render:

| Что | Переменные |
| --- | --- |
| Почта Gmail студии через Gmail API — так же, как в The Box 26 (HTTPS, работает на бесплатном Render) | `GOOGLE_MAIL_CLIENT_ID`, `GOOGLE_MAIL_CLIENT_SECRET`, `GOOGLE_MAIL_REFRESH_TOKEN`, `GOOGLE_MAIL_SENDER` — те же четыре переменные, их можно скопировать из The Box 26 как есть. Письма уходят с адреса из `GOOGLE_MAIL_SENDER`; имя отправителя берётся из `MAIL_FROM`, иначе «про.стим». Этот способ главнее остальных |
| Отправитель писем | `MAIL_FROM` (или `EMAIL_FROM`), например `Warkuda Games <noreply@домен>` |
| Почта через API (работает на бесплатном Render, где SMTP-порты закрыты) | `RESEND_API_KEY`, `BREVO_API_KEY` или `SENDGRID_API_KEY` |
| Почта через SMTP (Яндекс 360, Gmail, Mail.ru — на платном плане или другом хостинге) | `SMTP_HOST`, `SMTP_PORT` (465 или 587), `SMTP_USER`, `SMTP_PASS`. Подходят и имена из других проектов: `EMAIL_HOST` / `EMAIL_PORT` / `EMAIL_USER` / `EMAIL_PASS` (или `EMAIL_PASSWORD`), `MAIL_*` так же, а для Gmail хватит `GMAIL_USER` и `GMAIL_APP_PASSWORD` — сервер сам возьмёт `smtp.gmail.com` |
| Google | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` |
| Apple | `APPLE_CLIENT_ID` (Services ID), `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` (содержимое ключа `.p8`; можно одной строкой с `\n`). Секрет для Apple сервер подписывает сам (ES256) при каждом входе |
| Яндекс ID | `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` |
| GitHub | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` |
| Адрес сайта, если он не совпадает с адресом запроса | `PUBLIC_URL` |

Адрес возврата, который нужно указать у провайдера: `https://prostim.onrender.com/api/auth/oauth/google/callback`; для Apple, Яндекса и GitHub вместо `google` стоит `apple`, `yandex` или `github`. У Apple в Services ID ещё нужно указать домен `prostim.onrender.com`.

Сразу после запуска сервер пишет в лог, чем он отправляет письма и какие кнопки входа покажет, например: `Почта: resend (от noreply@…) · вход через: google, apple, github`. Если письма настроены через SMTP на Render, рядом будет напоминание, что на бесплатном плане SMTP-порты закрыты.

Пока почта не настроена, регистрация работает по нику и паролю, как раньше. С настоящим почтовым сервисом подтверждение почты становится обязательным; `REQUIRE_EMAIL=0` или `1` меняет это. Локально письма печатаются в консоль сервера, а `MAIL_TRANSPORT=outbox` складывает их в `data/outbox.jsonl`.

## Реклама и Плюс

Автор может продвинуть свой пост пакетом показов:

| Пакет | Показов | Цена |
| --- | --- | --- |
| 1 день | до 300 | 149 ₽ |
| 7 дней | до 3 000 | 790 ₽ |
| 30 дней | до 15 000 | 2 490 ₽ |

Как реклама выглядит в ленте:

- Продвигаемый пост встаёт после каждых пяти обычных, как в Reels. Реклама не ставится рядом с тем же постом.
- Рекламный пост узнаётся по свету, а не только по пометке: весь край экрана светится теми же цветами, что и подсказка перед ним. Линия прорисовывается от центра верхнего края, как только пост начинает въезжать на экран, поэтому её видно уже посреди свайпа. Ореол дышит, по рамке туда-сюда бежит яркая искра. Пометка «Реклама» и кнопка «Пропустить» тоже остаются: по закону о рекламе пометка обязательна.
- Пост перед рекламой подсвечивается снизу, как экран у новой Siri: по нижнему краю и закруглённым углам бежит тонкая цветная линия, над ней мягкий ореол. Свечение появляется сразу, как только пост встал на экран. Плашка «Дальше реклама · Пропустить» перескакивает рекламу одним нажатием.
- Два демо-поста («Между берегами» и Pulse) крутятся как реклама с самого начала, чтобы было видно, как это работает. `DEMO_ADS=0` их убирает.
- На рекламном посте — плашка «Реклама · @автор» (у карточки Плюса — «Реклама · про.стим»). Она не похожа ни на что другое на карточке, а нажатие открывает окно «Рекламный пост»: кто рекламодатель, что показы оплачены через продвижение, как часто стоит реклама и, без Плюса, строка «Лента без рекламы».
- Каждое третье рекламное место занимает сам про.стим: карточка подписки Плюс с кнопкой «Оформить».
- Показ засчитывается один раз на человека за полчаса, показы самого автора не считаются.
- Автор видит на странице поста, сколько показов из пакета прошло, сколько было переходов и до какого числа идёт продвижение. Продвижение кончается, когда исчерпаны показы или срок.

Подписка «про.стим Плюс» стоит 299 ₽ в месяц; первый оплаченный месяц — 149 ₽ (−50%). Она даёт:

- ленту без рекламы;
- значок «Плюс» в профиле;
- скидку 20% на продвижение;
- до 50 тестеров в тест-задании вместо 10 и место выше в списке заданий;
- значок Плюса (корона) у имени — в комментариях, ленте, на странице поста, в профиле, чатах и списках людей; на своём профиле по нему открывается Плюс;
- голосовые комментарии (без Плюса кнопка микрофона с короной открывает экран Плюса, сервер отвечает 402);
- оформление профиля — кнопка с палитрой на своём профиле (`POST /api/me/look`, каталог в `src/looks.js`). Редактор с живой карточкой сверху и вкладками: **Тема** — 18 тем, нарисованных CSS (ничего не грузится), в трёх группах: живые (Северное сияние, Синтвейв, Космос, Боке, Код, Глубина, Угли, Голограмма, Глитч), сцены (Неоновая вывеска, Закат над морем, 8 бит, Сакура, Комикс) и фактуры (Чертёж, Рельеф, Чёрный мрамор, Карбон), или своя картинка / GIF; **Аватарка** — украшение вокруг аватарки (нимб, орбита, пламя, корона, ушки, наушники, сердечки, снегопад, пиксели) и живая аватарка — GIF или видео до 10 секунд и 12 МБ; **Имя** — эффект имени (градиент, блеск, неон, радуга, огонь, глитч) и статус-эмодзи у имени; **Цвет** — 14 цветов профиля, без своего цвета берётся цвет темы. Тема, украшение, эффект имени и статус видны в профиле и в карточке по нажатию на имя, эффект и статус — ещё и у имени в комментариях. Без Плюса в редакторе можно всё примерить: у вещей из Плюса корона, а кнопка становится «Сохранить с Плюсом» и открывает экран Плюса. Оформление из Плюса видно, пока он действует;
- промпт с ИИ из комментария и остальное из раздела про экосистему.

**Карточка профиля.** Нажатие на имя или аватарку в комментариях открывает карточку человека, как в Discord: фон и цвет из оформления, живая аватарка, значок Плюса, звание помощи, рейтинг, о себе, цифры и кнопки «Подписаться», «Написать», «Профиль». На телефоне она выезжает снизу, на компьютере открывается рядом с именем.

На экране Плюса есть раскрывающаяся таблица «Без Плюса и с Плюсом» (`plusCompare` в `src/ads.js`): что работает бесплатно и что меняет подписка.

**Пробный день.** Кто ни разу не был в Плюсе, может включить его бесплатно на 24 часа (`POST /api/plus/trial`, один раз на аккаунт) — без карты, через сутки он просто выключается. Когда человек нажимает на платную функцию (например, «Промпт с ИИ»), открывается экран Плюса: анимированная шапка, что даёт подписка, кнопка «Попробовать бесплатно · 24 часа» и «Первый месяц за 149 ₽». После пробного дня сразу продолжается то, что человек хотел сделать. Тот же экран открывает рекламная карточка Плюса в ленте.

В профиле подписка не навязывается: она стоит скромной строкой в настройках («Изменить профиль → Подписка»). Кнопка «Продвинуть пост» остаётся на странице своего поста.

Оплата идёт через ЮKassa (карты, СБП, SberPay), когда заданы `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`. Адрес для уведомлений в кабинете ЮKassa: `https://prostim.onrender.com/api/payments/yookassa`. Статус платежа сервер всегда спрашивает у самой ЮKassa и не верит телу уведомления на слово.

Без этих ключей сайт работает в тестовом режиме: все шаги те же, но вместо страницы банка кнопка «Оплатить (тест)», деньги не списываются. `PAYMENTS_TEST=0` выключает тестовый режим.

## Лента, Steam и ИИ-мир — одна экосистема

Пост, папка проекта в ИИ-мире и заявка в Steam — это один проект. У автора на странице своего поста есть блок с пятью вкладками:

| Вкладка | Что там |
| --- | --- |
| Лента | Шесть цифр: следят, репосты, комментарии, сыграли в демо, переходы в Steam, тестеры; продвижение. Обновление и «Поделиться» — кнопками на самой странице, без повторов в блоке |
| Отзывы | Обзор для автора: оценка демо (средняя, разброс по звёздам, частые отметки); «Кто помог» — игроки по очкам помощи этому посту и чем именно (баг, идея, решение); все отзывы по группам «Баги», «Идеи», «Вопросы», «Решения», «Отзывы» с переключателем «Только неучтённые». Нажатие на отзыв открывает то же меню, что и удержание комментария. Когда выбрана группа с двумя и больше открытыми отзывами, их можно отдать ИИ одной задачей. На вкладке — число новых отзывов |
| Тестеры | Тест-задание: шаги, билд, промпт, доступ к папке; кто взял, кто отчитался, сколько шагов прошло (см. «Тест-задания» ниже). На вкладке — число новых отчётов |
| Код и ИИ | Связь поста с папкой на компьютере (ИИ-мир), последняя задача агента, «Собрать веб-демо» и «План по всем отзывам» |
| Steam | Статус (готовлюсь, заявка, скоро, вышла) и дата выхода; готовность из трёх частей: чек-лист автора, что показывает лента (следят 10, сыграли 20, досматривают 40%, переходов в Steam 10) и репозиторий (README, лицензия, скриншоты, собранный билд — проверяет агент на компьютере); тексты для страницы Steam; заявка издателю, заполненная из поста |

Связки между разделами:
- **Лента → ИИ-мир.** У комментариев к своему посту автор видит «Принять» и «В задачу ИИ»: отзыв уходит задачей для Claude Code или Codex в связанную папку. Пересказ «О чём пишут» отправляется туда же одной кнопкой — агент составит план правок.
- **ИИ-мир → Лента.** У выполненной задачи связанной папки есть «Опубликовать как обновление»: черновик собирается из запроса, ответа агента и последних коммитов, подписчики проекта получают уведомление. В шапке папки видно, к какому посту она относится.
- **ИИ-мир → Steam.** Тексты для страницы Steam пишутся из поста и README папки (с `ANTHROPIC_API_KEY` — силами Claude, без ключа — из текста поста), репозиторий проверяется на готовность.
- **Лента → Steam.** Переходы по ссылкам Steam считаются как интерес к игре. Когда игру смотрят до конца, сохраняют и ждут обновлений, приходит уведомление «Издатель заметил»: подай заявку — её посмотрят первой.
- **Steam → Лента.** На карточке — «Скоро в Steam» с датой и кнопка «В желаемое Steam» или «Вышла в Steam». Подписчики проекта узнают о статусе уведомлением, а в день релиза пост сутки продвигается бесплатно.
- В разделе Steam — «Мои игры на пути в Steam» с готовностью каждой.

### Отзывы на демо → задача ИИ → обновление

Цикл, ради которого всё связано:

1. **Игрок играет в демо прямо в посте** — с телефона, кнопкой «Играть». Если он пробыл в демо 15 секунд и больше, при закрытии появляется окно отзыва: 1–5 звёзд, отметки «Что понравилось» (графика, управление, звук, идея, атмосфера) и «Что мешало» (баги, сложно, непонятно, тормозит, мало контента), пара слов. В плеере есть и кнопка «Оценить». Отзыв становится комментарием со звёздами; оценка демо — средняя по последнему отзыву каждого игрока — видна на кнопке «Играть · ★4,3» на карточке и на странице поста. Автор свой проект не оценивает.
2. **Отзывы сортируются.** Человек сам помечает свой комментарий: баг, идея, отзыв, вопрос или решение; автор проекта может поправить пометку. Без пометки группу определяет сервер по словам: баги и проблемы (вылеты, тормоза, «неудобно», отметки «Баги» и «Тормозит»), идеи, вопросы, отзывы. Пометку видят все, догадку сервера — только автор (контурная метка).
3. **Автор отдаёт отзыв агенту** — из меню комментария: «В задачу ИИ как есть» или «Промпт с ИИ» (Плюс, см. ниже); несколько открытых отзывов одной группы — одной задачей из вкладки «Отзывы» (`POST /api/projects/:id/feedback-task`). Промпт по группам ставит баги первыми, со звёздами и отметками, и просит в конце перечислить, что сделано по каждому пункту. Игроки получают +10 искр.
4. **Агент закончил — автору приходит уведомление** «ИИ закончил задачу по …».
5. **Обновление из задачи закрывает отзывы.** Когда автор публикует обновление из этой задачи, отзывы получают метку «Учтено в обновлении», а их авторы — уведомление и +15 искр (один раз за отзыв).

### Тест-задания: комментаторы как тестеры

Автор может дать игрокам задание и среду, а получить отчёт по шагам. Во вкладке «Тестеры» блока проекта — «Создать тест-задание»:

| Поле | Что это |
| --- | --- |
| Что проверить и шаги | Название и до 10 шагов, по одному в строке. Черновик собирается из поста: с веб-демо — «открой демо и пройди обучение…», без него — «скачай билд…» |
| Билд или демо | Ссылка на сборку: веб-демо поста, itch.io, TestFlight, APK, облако |
| Платформа, версия, «как поставить» | Где проверять и что знать: тестовый аккаунт, установка, известные баги |
| Промпт для ИИ | Необязательно. Тестер скопирует его своему ИИ или, если ему открыта папка, запустит в ней — промпт ляжет в поле задачи |
| Папка проекта в ИИ-мире | Если пост связан с папкой: «только билд», «смотреть папку» или «ставить задачи ИИ». Доступ получают только взявшие задание, и он снимается, когда автор закрывает набор |
| Награда | Сколько искр автор добавит от себя к каждому принятому отчёту: нет, 10, 25 или 50. Искры уходят с баланса автора тестеру, по разу на отчёт; если на момент «Помогло» их не хватает, тестер получает только обычные 20, а автор видит подсказку. Задания с наградой стоят выше в списке |
| Мест | До 10, с Плюсом до 50 (сервер отвечает 402 на большее без Плюса). Задания авторов с Плюсом стоят выше в списке |

Как идёт цикл:

1. На карточке в ленте появляется метка «Ищут тестеров · +20», на странице поста — карточка задания с кнопкой «Стать тестером», в «Обзоре» — строка «Тест-задания» со всеми открытыми наборами (`POST /api/projects/:id/playtest/join`).
2. Тестер видит среду: кнопку билда или демо, платформу и версию, заметки, промпт, ссылку на папку. Отчёт — по каждому шагу «Прошло» или «Не прошло» с заметкой, общий отзыв, где проверял и до 4 скриншотов (`…/playtest/report`). Новый отчёт заменяет прошлый.
3. Отчёт становится комментарием: с проваленным шагом — «Баг», иначе — «Отзыв». В ветке он показан списком шагов с отметками, а в тексте комментария записан целиком, поэтому «В задачу ИИ» и пересказ получают все детали.
4. Автору приходит уведомление, на вкладке «Тестеры» — кто взял задание, кто отчитался и сколько шагов прошло. Нажатие на отчёт открывает меню комментария: «Помогло» (+20 искр тестеру), «В задачу ИИ», «Промпт с ИИ». Обновление из такой задачи закрывает отчёт как любой отзыв (+15 искр).
5. Позвать конкретного человека можно из меню его комментария: «Позвать в тестеры» — ему придёт уведомление (`…/playtest/invite`, один раз на человека).

Отчёты тестеров — ещё одна цель в готовности к Steam: «Отчёты тестеров, 5».

### Меню комментария

Удержи комментарий или нажми «··· Ещё» под ним — откроется меню. На телефоне оно всегда выезжает снизу, на одном и том же месте под пальцем: сверху сам комментарий и быстрые действия (ответить, ♥, копировать, «Помогло»), ниже — тип комментария отдельной строкой (он открывается своей панелью с описанием каждого типа), инструменты автора и удаление. На компьютере правая кнопка мыши открывает компактное контекстное меню прямо от курсора.

| Кто | Что в меню |
| --- | --- |
| Все | Ответить, ♥, скопировать текст, пожаловаться |
| Автор комментария | Пометить: баг, идея, отзыв, вопрос, решение (`POST …/comments/:cid/label`); удалить |
| Тот, кто спрашивал, — на ответ в своей ветке | «Это помогло»: ответ получает метку «Решение помогло», его автор — искры и очки помощи |
| Автор проекта | Пометить, «Помогло проекту», закрепить, «В задачу ИИ как есть», «Промпт с ИИ», удалить |

**Промпт с ИИ (Плюс).** Короткий отзыв вроде «кнопки мелкие» превращается в точную задачу: сервер берёт описание поста, всю ветку обсуждения, README и список файлов в корне папки (если компьютер в сети) и просит Claude написать задачу для агента — что заметил игрок, где искать в коде, как проверить (`POST …/comments/:cid/prompt`, без Плюса — 402). Без `ANTHROPIC_API_KEY` задача собирается по шаблону из того же контекста. Текст можно поправить; «Отправить и открыть папку» ставит задачу и сразу открывает папку проекта в ИИ-мире.

У комментария, который пригодился, все видят строку «Помог проекту» (или «Решение помогло») и что с ним стало: «автор отдал ИИ в работу», «учтено в обновлении».

### Помощь авторам

Отдельно от рейтинга (доверие людей, 1–5) у каждого есть **помощь** — насколько его комментарии пригодились чужим проектам. Очки дают действия автора, а не число сообщений:

| За что | Очки |
| --- | --- |
| Учтено в обновлении | +25 |
| Автор отдал отзыв ИИ | +15 |
| «Помогло» от автора проекта или от того, кто спрашивал | +10 |
| Комментарий закрепили | +5 |
| Оценка демо (раз на проект) | +2 |
| ♥ от других (до 5 на комментарий) | +1 |

Уровни: Зритель (0), Помощник (10), Тестер (40), Следопыт (100), Наставник (250), Соавтор (600), Опора сообщества (1500). В профиле помощь — одна из цифр рядом с подписчиками (очки и звание); нажатие открывает карточку с прогрессом, группами (баги, идеи, решения, отзывы), сильной стороной и числом проектов, которым человек помог. У имени в комментариях — звание. Уровень активности и рейтинг показывает только кольцо вокруг аватара: цвет — уровень, дуга и цифра под ней — рейтинг. На цифры «подписчиков» и «подписок» можно нажать — откроется список людей (`GET /api/users/:handle/people?list=followers|following`). Свои проекты очков не дают. Очки считаются на сервере заново из комментариев (`helpSummary` в `src/trust.js`), поэтому удалённый комментарий или снятое «Помогло» их убирает.

**Веб-демо через агента.** Во вкладке «Код и ИИ» кнопка «Собрать веб-демо» ставит агенту задачу собрать HTML5/WebGL-версию и выложить её туда, где проект уже настроен: GitHub Pages, itch.io (butler), Netlify, Vercel или Cloudflare Pages. Ссылку из ответа агента сервер находит сам; автору приходит уведомление, а в блоке проекта — «Веб-версия готова · В пост». Ссылку можно поставить и из истории задач в ИИ-мире. Подписчики проекта узнают о новой версии демо уведомлением.

**Плюс — на все три раздела:** без рекламы и скидка 20% на продвижение в ленте плюс бесплатный день продвижения раз в месяц; в ИИ-мире до 6 компьютеров вместо 2, файлы до 100 МБ вместо 25 и история 200 задач вместо 60 на папку; в Steam заявку смотрят первой и бесплатно проверяют документы.

**Искры** — награда за помощь авторам: +20, когда автор принял отчёт, +10, когда отзыв взяли в работу ИИ, +15, когда его учли в обновлении, +10 за закреплённый комментарий (каждая награда за один комментарий — один раз, автор раздаёт не больше 15 наград в сутки). Больше всего искр приносят тест-задания: отчёт по шагам легко принять. Баланс видит только владелец: на своём профиле рядом с ником — маленькая плашка с искрой и числом, другим она не показывается (сервер отдаёт искры только в `account`). Нажатие открывает окно об искрах: баланс, как получить, история и кнопка «Магазин искр». Строка «Искры» в настройках осталась.

**Магазин искр** (`#/sparks`): неделя Плюса (300), день продвижения своего поста (100, пост выбирается тут же) и оформление навсегда — вещи, которые покупаются один раз и остаются даже без Плюса (`POST /api/shop/buy`, список — `sparkItems` в `src/looks.js`): темы «Кузница искр» (400) и «Галактика» (600), украшения «Искры» (250) и «Молнии» (300), эффект имени «Золото» (200). Купленное хранится в `owned` аккаунта и надевается кнопкой «Надеть» в магазине или в редакторе оформления; там же неоплаченную вещь можно примерить, и кнопка сохранения становится «Купить за N искр и сохранить».

**Пульт автора** — вкладка с ракетой на своём профиле (`#/me/desk`), когда есть свои проекты. Каждый проект — одна карточка по трём разделам: Лента (новые отзывы и отчёты тестеров, иначе комментарии и подписчики), ИИ-мир (связанная папка, в сети ли компьютер, статус последней задачи, или «Свяжи с папкой») и Steam (готовность в процентах и статус). Ниже — что ждёт автора: готовая веб-версия, задача ИИ, законченная после последнего обновления, места в тест-задании. Сверху — сколько всего ждёт, такие проекты стоят первыми. Каждая часть ведёт туда же, куда вкладки блока проекта на странице поста. У «Мои игры на пути в Steam» в разделе Steam есть ссылка на Пульт.

## Уведомления и приложение

Колокольчик справа вверху ведёт на экран «Уведомления» (он же есть первой строкой во «Входящих»): новые подписчики, поддержка, комментарии, отзывы на демо, ответы, ♥ на комментарии, закрепы, «твой отзыв учли», репосты, обновления проектов, готовые задачи ИИ и новая веб-версия, новые проекты авторов из подписок. Однотипные события по одному посту собираются в одну строку: «Аня и ещё 3 поддерживают…». Новые события приходят сразу, по SSE.

Push-уведомления приходят, даже когда сайт закрыт. Сайт спрашивает разрешение не при входе, а когда это полезно: после первого комментария, подписки, «Следить» или сообщения. В настройках профиля → «Уведомления» можно выбрать, что присылать, включить тихие часы (23:00–8:00 по часовому поясу устройства), проверить доставку и выключить push на этом устройстве. Сообщения из чатов тоже приходят push, но в список не попадают — для них есть «Входящие».

Сайт ставится как приложение: в Chrome, Edge и Яндекс Браузере — кнопкой в настройках уведомлений или в адресной строке, на iPhone — «Поделиться» → «На экран „Домой“». На iPhone и iPad push работает только из установленного приложения (iOS 16.4 и новее), сайт подсказывает это сам.

| Переменная | Что делает |
| --- | --- |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Ключи Web Push (base64url, P-256). Без них сервер создаёт пару сам и хранит в базе; задавать нужно, только чтобы ключи не зависели от базы |
| `PUSH_SUBJECT` | Контакт для push-сервисов (`mailto:…` или `https://…`). По умолчанию — адрес сайта, с которого подписался первый браузер |

Push отправляются только на адреса известных сервисов (Google, Apple, Mozilla, Microsoft, Яндекс); подписка с другим адресом отклоняется. Шифрование проверено на контрольном примере из RFC 8291.

## Комментарии

На комментарий можно ответить (ответы идут под ним веткой; ответ на ответ остаётся в той же ветке и начинается с @ника), поставить ♥, автор проекта может закрепить один комментарий сверху и удалить любой. У комментариев автора проекта рядом с именем стоит метка «Автор». Порядок — «Лучшие» (свежие и залайканные вперемешку: лайки и ответы поднимают, каждый час возраста опускает), «Новые» или «Популярные»; закреплённый всегда первый. В длинных ветках виден первый ответ и кнопка «Ещё N ответов». Голосовой комментарий записывается кнопкой с микрофоном, до двух минут; файл хранится как обычная загрузка. Под заголовком «Комментарии» от трёх штук появляется «О чём пишут»: короткий пересказ обсуждения.

Пересказ без ключа ИИ собирается простым подсчётом: сколько хвалят, жалуются, спрашивают и о чём пишут чаще всего. Если задан `ANTHROPIC_API_KEY`, пересказ пишет Claude (`claude-opus-5-5`, модель меняется переменной `AI_MODEL`), а пересказ получает пометку «ИИ». С тем же ключом Claude причёсывает черновик поста по ссылке: короткую строку, абзацы и список особенностей. Сервер включает резервную модель на случай отказа (`fallbacks: "default"`); при любой ошибке используется простой вариант.

## Настройки и тема

Нижняя панель на телефоне видна всегда и прячется только под открытую клавиатуру: клавиатурой считается поле ввода в фокусе плюс заметно уменьшившийся экран, а не свернувшаяся панель браузера или увеличение пальцами. Шторка с полем ввода поднимается над клавиатурой. Под панелью оставлена только часть системного отступа для полоски «Домой», как у нативных приложений. В приложении с экрана «Домой» на iOS 26 страница, которая короче экрана (лента), раскладывается короче на высоту статусной строки, и ниже этой границы WebKit ничего не рисует (ошибка WebKit 301108). Поэтому в режиме приложения документ всегда растянут на весь экран: `html { min-height: min(100lvh, calc(100% + env(safe-area-inset-top))) }` — так iOS отдаёт странице полную высоту, а `min()` не даёт ей прокручиваться.

iOS 26 сам рисует размытие от верха установленного приложения примерно на 40 точек ниже статусной строки, поверх страницы — перекрыть его нельзя. Поэтому в приложении на iPhone (класс `ios-app` на `html`) верхняя строка с разделами и всё, что к ней привязано, опущены на 12px ниже, из самой плотной части размытия: переменная `--safe-t`.

Шестерёнка справа вверху на своём профиле ведёт на страницу настроек: профиль, вход и почта, Плюс, приватность, уведомления, лента, тема и установка приложения. Карточка «Лента знает тебя» ушла с профиля в «Твоя лента».

| Раздел | Что можно |
| --- | --- |
| Конфиденциальность | Кто может писать: все, мои подписки или никто (тот, кто написал первым, ответить может всегда). Кто комментирует мои проекты: все или мои подписки. Показывать ли мои репосты. Список заблокированных |
| Лента | «Твоя лента», звук видео по умолчанию, экономия трафика (видео не играют сами, следующие посты не грузятся заранее), сброс интересов |
| Оформление | Тема: как на устройстве (по умолчанию), тёмная или светлая. Лента в любой теме остаётся тёмной, а шторки поверх неё следуют теме |

Аватарка перед загрузкой кадрируется: фото двигается пальцем или мышью, масштаб — ползунком, колёсиком или двумя пальцами, круглая маска показывает, что попадёт в аватарку.

## Безопасность

У поста, комментария, пользователя и сообщения есть «Пожаловаться» с причиной. Жалоба сразу скрывает пост или комментарий у того, кто пожаловался. Пост, на который пожаловались `REPORT_HIDE` разных людей (по умолчанию 5), скрывается у всех, кроме автора; комментарий — после `REPORT_HIDE − 2`, но не меньше двух. Если задан `REPORTS_EMAIL` и настроена почта, каждая жалоба приходит письмом.

Блокировка (меню «…» на посте или в профиле) снимает подписки в обе стороны и скрывает посты и комментарии друг друга; заблокированный не может написать, прокомментировать или подписаться. Список заблокированных — в настройках профиля.

## Сообщения

Пост можно отправить в чат карточкой: «Поделиться» → аватар человека из переписок или подписок. Там же — ссылка, Telegram и VK.

В чате есть панель эмодзи и набор стикеров: эмодзи с подписью на цветной плашке, нарисованные в CSS, без картинок. Сообщение из одних эмодзи показывается крупно. Скриншот или фото отправляется кнопкой с картинкой: браузер сжимает его, и он приходит в чат превью, которое открывается на весь экран.

На любое сообщение можно поставить реакцию: двойной тап ставит ❤️, долгое нажатие или правый клик открывает полоску из восьми реакций. У каждого человека одна реакция на сообщение; повторный выбор той же реакции её снимает. Сервер принимает только реакции из списка в `src/chat.js` и только от участников переписки.

Голосовой ввод — кнопка с микрофоном в чате и в задачах ИИ-мира. Речь распознаёт сам браузер (Web Speech API, русский язык), текст появляется в поле по ходу речи. Где браузер этого не умеет, кнопки нет.

## ИИ-мир

1. В разделе «ИИ-мир → Подключить» сайт выдаёт код привязки и команду.
2. Команда на компьютере скачивает агент и запускает его в папке проекта:

   ```sh
   node ~/prostim-agent.mjs --server https://адрес-сайта --code ABCD-EFGH --dir . --allow edit
   ```

3. Агент держит исходящее соединение с сервером (SSE), получает задачи и запускает Claude Code (`claude -p --output-format stream-json`) или Codex (`codex exec --json`). Каждое событие — мысли, чтение и правка файлов с diff, команды и их вывод, итог и стоимость — приходит на сайт в реальном времени.
4. Повторный запуск: `node ~/prostim-agent.mjs`. Ещё одна папка: `--dir путь`. Настройки лежат в `~/.prostim/agent.json`.

Предел доступа задаётся на компьютере флагом `--allow`: `read` — анализ без изменений, `edit` — правки файлов, `full` — правки и команды без подтверждений. Сайт не может запросить больше. Владелец проекта может открыть другим людям просмотр или постановку задач; полный режим доступен только владельцу. Файлы проекта на сервер не копируются: передаются задача, шаги, diff и файлы, которые пользователь открыл.

К задаче можно приложить до 8 файлов по 25 МБ: фото, скриншоты, видео, аудио, документы — скрепкой в поле задачи. Файлы закрыты: по публичной ссылке их не открыть, скачать их может только компьютер, на котором выполняется задача. Агент 0.3.0 и новее кладёт их в папку проекта `.prostim/inbox/` (вместе с `.gitignore`, чтобы они не попали в коммиты) и дописывает к задаче их пути. Если на компьютере агент старше, сайт подсказывает его обновить.

Если Claude Code или Codex не установлены или в них не выполнен вход, агент работает в демо-режиме и подсказывает, что сделать.

## Визуальный стиль

У каждого раздела свой дизайн-код, чтобы они не смешивались. Цвет акцента задаётся переменными `--accent` и `--brand` на `main` и окнах раздела (`body[data-section]` в `styles.css`), поэтому одни и те же компоненты сами окрашиваются в цвет раздела.

| Раздел | Акцент | Мотив |
| --- | --- | --- |
| Лента, обзор, сообщения, профиль | Белый `#f2f1ee` на чёрном, «Кино», плюс фирменный градиент `--grad`: красный `#ff2e63` → коралловый → янтарный `#ffb03b` | Текст и поверхности монохромные, градиент — только на главном: логотип, «+», новое и «по вкусу», текущий слайд, стадия проекта, подписка, свои сообщения в чате. Лайк на телефоне горит красным `--hot`, сохранение — янтарным `--amber`. У категорий свой оттенок: игры красные, приложения янтарные, инструменты голубые |
| Steam | Голубой Steam `#9fcaff` | Сталь после горелки и перламутр: цвета побежалости (соломенный, бронза, фиолетовый, синий, голубой) с чёткими переходами. Стальные цифры с бегущей полосой побежалости (`.chrome-text`), «2%» целиком в побежалости (`.iri-text`), капля металла, окрашенная полосами через `mix-blend-mode: color` (`liquidHtml()`), волны (`wavesSvg()`), полоса 98/2 — стальная лента и перламутр |
| ИИ-мир | Фиолетовый `#b9a3ff` и бирюзовый `#67e8f9` | Нейроядро с орбитами (`neuralHtml()`), сетка точек на фоне, моноширинные подписи |

Фон Steam — почти чёрный с холодным отсветом, мелким зерном и редкой «пыльцой» (`--grain`, `--dust`: SVG-шум в CSS, без картинок). То же зерно, только мягче (`--grain-soft`), лежит на шапке и блоке 98/2.

Отступы между секциями страницы задаёт одна переменная `--stack`: 22 px на компьютере и планшете, 14 px на телефоне. Раскладка проверена на ширине 320 (iPhone SE), 393 и 430 (обычные и большие iPhone), 768 (iPad), 1024 и 1440 пикселей. На экранах до 360 px верхнее меню и кнопки профиля ужимаются, а теги в карточках ленты на телефоне стоят в одну строку и плавно гаснут к краю.

Логотип — арка (буква «П» и ворота, через которые проект выходит к людям) с точкой из «про.стим» внутри, белым по фирменному градиенту (`logoMark` в `icons.js`, та же картинка во вкладке браузера). Общие части приложения остаются единого вида: логотип, нижнее меню и экран загрузки не перекрашиваются. Полоска под «Лента · Steam · ИИ-мир» берёт цвет раздела и плавно переезжает при переходе. Бейдж «ИИ» в ленте и переключатель «Сделано с ИИ» — цвета ИИ-мира.

Под лентой страница не прокручивается: лента — свой собственный прокручиваемый блок, поэтому на iPhone ничего не съезжает и снизу не выглядывает следующая карточка. Пока открыто окно или шторка, страница под ним тоже стоит на месте. Закрытое окно никогда не занимает места (`dialog:not([open])`). Когда меняется высота экрана (например, прячется панель Safari), текущая карточка остаётся на месте.

**Тактильный отклик.** Лайки, сохранения, подписки, вкладки, нижнее меню, переключатели, звёзды отзыва, шаги тест-задания, порог «потяни, чтобы обновить» и смена высоты шторки отвечают лёгким щелчком, успехи (публикация, отчёт, оплата, «Помогло») — двойным, ошибки в формах — тройным. На Android это Vibration API, на iPhone (iOS 18 и новее) — Taptic Engine: Safari не даёт вибрации сайтам, но переключатель `<input type="checkbox" switch>` при нажатии щёлкает моторчиком, поэтому сайт нажимает невидимый переключатель. Выключается в настройках: «Оформление → Отклик при нажатиях».

Анимированный логотип (`logoLoaderHtml()`) показывается при загрузке сайта и при обновлении ленты. Новый экран въезжает с той стороны, куда идёт переход. Декоративные анимации стоят на паузе, пока листается лента, а при системной настройке «уменьшить движение» отключаются.

## Хостинг

`render.yaml` в корне репозитория описывает веб-сервис и бесплатную базу Postgres на Render. Бесплатный сервис засыпает после 15 минут без запросов и просыпается примерно за минуту. Запущенный агент обращается к серверу каждые 25 секунд, поэтому, пока он работает, сайт не засыпает.
